Analyse du notebook de reference

Lecture et comprehension du notebook microsoft-security-incident.ipynb fourni comme reference methodologique.

  • Dataset source : GUIDE_Train.csv / GUIDE_Test.csv (Microsoft Kaggle, 9.5 millions de lignes)
  • Objectif : predire le triage d'incident en 3 classes : TruePositive, BenignPositive, FalsePositive
  • Pipeline : nettoyage → encodage → XGBoost avec K-Fold Cross Validation
  • Meilleurs hyperparametres identifies : max_depth=15, n_estimators=200, lr=0.3
  • Performances originales : Accuracy 93.7%, AUC-ROC 0.99 sur 4.1M de lignes de test

Analyse du fichier Incident.csv issu de l'environnement Microsoft Sentinel.

  • 2 363 lignes au total, 31 colonnes
  • 871 incidents classes (Classification non nulle) → filtre sur TP / BP / FP

  • Distribution des classes : BenignPositive 528 • FalsePositive 205 • TruePositive 31

Analyse de la fiabilite du modele

Evaluation critique des performances pour un usage en production SOC :

Points positifs :

  • AUC-ROC macro = 0.926 → bonne discrimination globale
  • BenignPositive F1 = 0.92 → classe majoritaire bien apprise
  • CV stable : 0.865 ± 0.017

Problemes identifies :

  • Overfitting : Train 100% vs Test 89% → max_depth=15 trop profond pour 611 echantillons
  • TruePositive recall = 50% → le modele rate 1 vrai incident sur 2 (inacceptable en SOC)
  • Dataset trop petit : 764 echantillons vs 9.5M dans le notebook original
  • Desequilibre de classes : seulement 31 TruePositive
Verdict : Modele utilisable pour le pre-filtrage BP/FP avec supervision humaine. Non recommande pour la detection automatique de TruePositive en production sans correction du desequilibre.

Pistes d'amelioration :

  • Reduire max_depth a 4-6 pour eviter l'overfitting
  • Utiliser scale_pos_weight ou SMOTE pour equilibrer les classes
  • Enrichir le dataset avec plus de TruePositive
  • Ajouter des features securite (MITRE techniques, type d'entite)

Integration dans le Dashboard Sentinel

Integration end-to-end du modele XGBoost dans l'interface web du Sentinel Log Viewer.

Architecture mise en place :

Alerts Page (Next.js) ↓ fetchMlGrades(alerts) [parallele pour chaque incident] /api/incident-grade (Next.js route.ts) ↓ POST /predict ML Server FastAPI :8004 (scripts/ml_server.py) ↓ charge le modele pkl XGBoost Model → { label, confidence, probabilities } ↑ Badge ML affiche sur chaque carte d'incident

Fichiers crees / modifies :

FichierActionDescription
scripts/xgboost_benchmark.pyModifieSauvegarde des encodeurs categoriels dans le pkl

Badge ML affiche sur chaque incident :

  • False + — fausse alerte (bleu) + % confiance
